# 视频广告去除工具（Video Ad Cutter）

自动检测视频中的转场 / 硬切，把视频切成一段段；在界面上预览每一段的
首帧并勾选要**删除**的片段（例如开头被附加的广告），最后把保留的片段
**用主视频（去掉广告后的主体部分）的原编码拼接**成新视频。

> 核心设计（最新）：切割与拼接**全程使用主视频的原编码流拷贝（`-c copy`）**，
> **不做任何重新编码**。因此画质零损失、输出编码与源 100% 一致，且
> **体积严格正比于「保留时长」** —— 删掉片头后文件必然变小，不会因重编码而膨胀。

---

## 运行环境

- Windows 10 / 11
- 视频处理依赖 **ffmpeg**（用于 demux / remux 流拷贝），建议用自带的 `ffmpeg/bin/` 版本。
- ⚠️ 导出走的是**原编码流拷贝，不重新编码**，因此**不再需要 GPU / NVENC 编码器**；
  ffmpeg 仍必须（做流的解封装 / 重封装），但导出本身不调用 h264_nvenc 等编码器。
- 转场检测基于 ffmpeg `scdet` 滤镜（自适应阈值），**无需下载任何模型权重**，CPU 完成。

> 转场检测属于「逐帧内容分析」，GPU 加速并不体现在编码阶段（因为本工具不重编码）。
> 除非你的视频索引缺失需要重建（见下），否则全程不依赖外部大模型或权重文件。

## 快速开始

1. 双击 `启动.bat` 启动图形界面（自动激活 `venv` 虚拟环境，
   并把自带的 `ffmpeg` 加入 PATH）。
2. 点击「选择视频」选中文件。
3. 点击「检测转场」，等待切分完成（会扫描整段视频）。
4. **窗口启动时自动最大化**；检测完成后，每行缩略图张数按当前窗口宽度自动计算
   （屏幕越宽每行越多，至少 3 张），不再固定每行 3 张。
   界面会列出每一段：缩略图 + 时间段 + 分辨率，默认全部「保留」。
   取消勾选 = 删除该片段（例如取消开头的广告段）。
   - 缩略图已适配本机：直接显示每段首帧（绕开了被「应用程序控制策略」拦截的
     Pillow `_imagingtk` DLL，改用 Tk 原生 PNG 解码，不再出现「预览生成失败」）。
   - 点击缩略图本身即可切换「保留 / 删除」状态，保留段会有鲜红高亮边框。
   - **按住 Shift 批量处理**：先点一张图（普通点击或 Shift 点击都行）作为起点，
     再按住 Shift 点另一张，两张之间（含这两张）的所有片段会统一设成起点那张
     的状态。所以「Shift 点第一张广告 → Shift 点最后一张广告」即可整段取消；
     反过来先 Shift 点一张已取消的，则整段恢复选中。状态栏会提示实际处理的范围。
   - 底部按钮：**「全部选中」** / **「全部取消(删除全部)」**。
5. 底部「目标规格」标签会随勾选实时更新，现显示：
   **「输出规格(主视频原编码·流拷贝，不重新编码)」**。
6. 点击「导出视频」即可，**不再弹保存对话框**：输出文件固定写到
   **源视频所在目录**，文件名 = `原文件名-adcut.原扩展名`
   （如 `电影.mkv` → `电影-adcut.mkv`）。顶部绿色标签会实时显示实际输出路径；
   若同名文件已存在，自动追加 `_2` / `_3` …，**不会覆盖**已有文件。
7. 导出时底部状态栏会实时显示进度，例如
   `正在合并第 2 段视频，共 4 段（47%）`，以及开始时的
   `开始导出：共保留 4 段视频…`；全部保留且首尾相连时则显示
   `正在合并为最终视频（保留 4 段，已首尾相连无需逐段切分）`。
8. 完成后可点「打开输出目录」查看结果。

## 命令行（无界面）用法

```bat
venv\Scripts\activate
python merger.py "输入.mp4" "输出.mp4" "10-30,40-60"
```

第三个参数是「保留」的时间区间（秒），逗号分隔；其余部分被删除。

> ⚠️ 注意：当前 `merger.py` 的命令行入口（`__main__`）走的是**旧的重新编码路径**
> （`merge()`，libx264 `-crf 21`），与 GUI 默认的「原编码流拷贝」路径**不同**。
> 若希望命令行也用流拷贝，请直接以模块方式调用
> `merger.merge_streamcopy(video_path, kept_segments, out_path, app_dir=...)`。

## 处理要点（最新行为）

### 1. 原编码流拷贝（默认路径）
- **切割**：逐段用 `-ss … -i 源 -t … -c copy` 直接拷贝压缩流，不解码、不重编码。
- **拼接**：用 `concat -c copy` 把保留段按原样拼起来。
- **结果**：输出文件的编码、像素格式、码率结构**与源完全一致**；
  体积严格随「保留时长」成比例，**删掉片头必然变小**（旧的重编码路径曾因 CRF 21
  把每帧塞进更多码率，导致体积不减反增，现已根除）。

### 2. 关键帧对齐的取舍（必读）
流拷贝的切点只能落在**最近关键帧**上，因此输出时长可能比「检测到的保留段」
**多出约一个 GOP**（边界前相邻的非关键帧也会被保留）。这是「不重新编码」方案的
必然代价 —— 换来的是**体积不涨、画质零损**。若你需要精确到帧的切割，则必须
重编码（又回到体积膨胀），二者不可兼得。

### 3. 索引缺失 → 自动重建重试
若某段切割失败，且 ffmpeg 报错「像」视频索引 / moov 缺失
（`moov atom` / `could not find codec` / `invalid data found` /
`non-monoton` / `index` 等关键词），工具会：
1. 用 `-c copy -movflags +faststart` 重建索引（把 moov 移到文件头）；
2. 用重建后的文件**重试一次**流拷贝。

### 4. 其他错误 → 详细日志落盘
若仍失败且不属于「索引问题」，工具会**不做任何重新编码**，并把完整的排查信息写入
**应用目录（video-ad-cutter/）** 下的日志文件：

```
vacut_error_<YYYYMMDD_HHMMSS>.log
```

日志内含：源视频路径、目标输出路径、ffmpeg 命令、返回码、完整 stderr、
以及逐段保留片段清单，便于你直接定位问题。

### 5. 转场检测
- 默认用 `detector_ffmpeg.py`（基于 ffmpeg `scdet` 滤镜，自适应阈值），
  无需逐帧 Python 循环，大视频明显更快；
- 任意失败自动回退到 `detector.py`（OpenCV 逐帧像素差异实现），API 一致；
- 广告 → 主片的画幅 / 内容突变会被高差异捕获为新的片段起点。

## 常见问题

- **导出后体积怎么比源小了？** 正常。因为走的是原编码流拷贝，体积正比于保留时长；
  删掉片头自然变小。这正是本工具相对「重编码」方案的优势。
- **导出时长比勾选的保留段多了几秒？** 属于流拷贝的「关键帧对齐」取舍（见处理要点 2），
  边界前的相邻帧被一并保留，属正常现象，不影响去广告效果。
- **提示「预览生成失败」？** 本机已修复：改用 Tk 原生 PNG 解码绕开被拦截的
  Pillow `_imagingtk` DLL，正常情况应直接显示每段首帧。
- **导出失败且生成了 `vacut_error_*.log`？** 说明遇到了非索引类的流拷贝错误，
  打开该日志查看 ffmpeg 的详细报错（命令 / 返回码 / stderr / 片段清单）即可定位。
- **检测把正片也切得太碎？** 可在 `detector_ffmpeg.detect_scenes` /
  `detector.detect_scenes` 调高阈值以减少误切。
- **未检测到 ffmpeg？** 确认 `ffmpeg\bin\ffmpeg.exe` 存在（启动器会自动加入 PATH），
  或系统 PATH 中已有可用的 ffmpeg。
